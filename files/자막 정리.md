### 파일시스템 기준

##### 흐름
  - 파일 시스템을 탐색하면서 자막 파일을 찾음
  - 자막이 Plex DB에 등록 되어 있는지 확인
  - 없으면 자막에 맞는 비디오 파일이 같이 있는지 확인
  - 비디오 파일이 Plex DB에 등록 되어 있는지 확인 
  - 등록되어 있으면 자막만 갱신하기 위해 웹-메타새로고침 실행
  - 등록되어 있지 않다면 비디오와 같이 등록하기 위해 스캔(Binary) 실행  
  
##### smi2srt On
  - subtitle_tool 플러그인 설치 필요
  - smi 자막이 DB에 등록되어 있거나, 비디오 파일이 있을 경우에만 수행  
    비디오 파일없이 smi 자막만 있는 경우 무시. 
  - 비디오 파일은 .smi 제외한 동일한 파일명이 있는 경우에 한함.  
  - 변환 후 smi 삭제. ko.srt 파일 생성
  - 변환 안되는 smi 파일들이 있음.
    smi 포맷이 아니거나, Sync Sstart 같은 오타가 포함되는 등 원인이 매우 다양함.  
    subtitle_tool 플러그인 로그로 원인 확인 필요.

##### 주의사항
  - 메타새로고침은 동기화 작업이 아님.   
    Plex에 스캔하라고 명령만 전달하기 때문에 실제 반영은 나중에 됨.   
    Plex 작업 종료 후 재실행하여 파악 할 것  
  - 부가영상 폴더는 처리하지 않음.
  * 분석 예
    - 자막만 있고 비디오 파일이 없는 경우

### DB 기준 자막 정리

##### 개요
- 파일 시스템을 전수 스캔하지 않고, **Plex SQLite DB의 데이터를 기반으로 빠르고 안전하게 자막 상태를 진단하고 정리**합니다.
- 삭제된 자막(죽은 자막) 정리와 외화 컨텐츠의 한글 자막 누락 진단을 필요에 따라 개별 또는 전체로 실행할 수 있습니다.
- 4만 편 이상의 대용량 라이브러리에서도 대부분의 검사가 메모리/DB 연산으로 이루어져 **구글 드라이브(Rclone) API 차단 위험이 전혀 없습니다.**

##### 실행 모드 및 버튼

1. **`[DB 죽은자막 정리 (1·2단계)]`**
   - **1단계: 외부 자막 무결성 검사 (죽은 자막 탐지)**
     - Plex DB에 등록된 외부 자막(`.srt`, `.smi` 등) 파일이 실제 디스크에 존재하는지 병렬(ThreadPool 8스레드, 파일당 5초 타임아웃)로 고속 검사합니다.
     - Rclone 무한 대기 현상을 방지하여 멈춤 없이 안정적으로 검사합니다.
   - **2단계: 죽은 자막 메타 새로고침**
     - 디스크에서 삭제된 자막(죽은 자막)이 발견된 경우, 영화 또는 TV 쇼 단위로 중복 없이 묶어서 Plex에 메타 새로고침을 지시합니다.
     - 메타 새로고침을 통해 Plex DB에서 죽은 자막 정보가 자동으로 정리됩니다.
     - Plex 서버 부하 방지를 위해 호출 간 **0.1초 안전 텀**이 적용됩니다.

2. **`[DB 외화자막 진단 (3단계)]`**
   - **외화 한글 자막 누락 진단**
     - 외화(외국 영화, 해외 드라마)를 대상으로 한글 자막이 누락된 영상을 정밀 진단합니다.
   - **스마트 오탐 방지 및 자막 검사**:
     - **국내/한국 라이브러리 자동 제외**: 라이브러리 이름에 `한국`, `국내`가 포함되어 있거나 컨텐츠의 국가(Country) 메타데이터가 한국인 경우 누락 진단을 건너뜁니다.
     - **MKV 내장 자막 완벽 인식**: 비디오 컨테이너 내부에 포함된 다국어 스트림(`media_parts` 조인 및 `extra_data` 언어 코드 분석)을 검사하여, 내장 한글 자막이 있는 컨텐츠는 정상으로 분류합니다.
   - **디스크 자막 감지 및 즉시 메타 새로고침**:
     - Plex DB에는 자막이 등록되어 있지 않지만, 비디오 파일과 동일한 폴더에 `.ko.srt`, `.srt`, `.ko.smi` 등의 자막 파일이 디스크에 실제로 존재하는 경우 **즉시 메타 새로고침을 지시하여 Plex DB 등록을 유도**합니다.
     - 파일명에 관계없이 디스크에 자막 파일이 있으면 무조건 감지하여 새로고침하며, TV 드라마의 경우 여러 에피소드에서 자막이 발견되어도 **쇼 1개당 딱 1번만 새로고침**하도록 중복 방지 캐시가 적용됩니다.
   - **자막 누락 목록 및 자체자막(SW/ST/KOR) 힌트 안내**:
     - 디스크에도 자막이 전혀 없는 영상만 주황색 `[외화 한글자막 누락]` 카드로 출력됩니다.
     - 만약 파일명에 `-ST`, `-SW`, `KOR` 등의 태그가 포함된 경우 `[파일명 'SW' 감지: 영상 자체자막일 가능성 있음]` 안내 문구를 목록에 함께 표시하여, 사용자가 불필요하게 자막을 다시 구하는 혼선을 방지합니다.

3. **`[DB 전체 실행]`**
   - 1단계(죽은 자막 탐지) ➔ 2단계(죽은 자막 메타 새로고침) ➔ 3단계(외화 자막 누락 진단 및 디스크 자막 감지) 순서로 일괄 자동 진행합니다.

##### 성능 및 안정성 최적화
- **브라우저 프리징 방지**: 실시간 검사 로그를 DOM 200개로 자동 유지 관리하여, 수만 건의 검사 시에도 웹 UI가 느려지거나 뻗지 않습니다.
- **웹소켓 쓰로틀링**: 상태 알림을 0.5초 간격으로 조절하여 통신 부하를 최소화했습니다.
- **서버 쿨다운**: 메타 새로고침 호출 사이에 0.1초 딜레이를 두어 Plex Media Server 큐가 안정적으로 소화되도록 보호합니다.
- **메타 새로고침 완료 항목 상단 고정 표기**: 실시간 검사 로그가 200개를 초과하여 지나가더라도, 실제 메타 새로고침이 요청된 영화/쇼 목록은 화면 상단 카드에 요청 시각, 컨텐츠명, 감지된 자막 파일명, 요청 성공 여부와 함께 별도로 영구 유지되어 새로고침 결과를 한눈에 쉽게 파악할 수 있습니다.

##### `smi to srt` 옵션 연동 (DB 검사 모드)
- 설정 메뉴의 **`smi to srt` (`subtitle_use_smi_to_srt`)** 옵션이 활성화되어 있을 경우, DB 기반 자막 검사에서도 파일 변환 및 복사 생성이 자동으로 수행됩니다:
  1. **`.smi` 자막 발견 시**: `subtitle_tool` 플러그인을 호출하여 `.ko.srt`로 자동 변환 생성합니다. 이미 `.ko.srt`가 존재하면 중복 변환을 건너뛰며, Rclone merge/union 등 읽기 전용이나 삭제 제한 환경을 고려하여 원본 `.smi`는 삭제하지 않고 안전하게 보존합니다.
  2. **일반 `.srt` 자막 발견 시 (언어 태그 없는 `.srt`)**:
     - **외국어 자막 철저 배제**: 파일명에 외국어 언어 코드(`eng`, `ja`, `chi` 등) 또는 서브태그(`.sdh`, `.forced`, `.cc` 등, 예: `.eng.sdh.srt`)가 명시되어 있거나, Plex DB에 외국어로 등록된 자막은 절대 변환하지 않고 스킵합니다.
     - **중복 처리 완벽 방지**: 대상 `.ko.srt` 파일이 이미 디스크에 존재하거나 해당 영상에 정식 `.ko.srt`가 이미 있는 경우 추가 생성/새로고침 없이 즉시 스킵합니다.
     - **실제 한글 대사 정밀 판별**: 단순 크레딧 1줄이나 인코딩 오인을 방지하기 위해, 파일 내에 **최소 20글자 이상의 완성형 한글(`가-힣`) 대사**가 유효하게 확인된 경우에만 `.ko.srt` 파일로 복사 생성합니다.
  3. **1단계 (외부 자막 검사)**: 기존에 DB에 등록되어 있던 `.smi` 자막이나 순수 한글 `.srt` 자막을 확인하여 `.ko.srt`를 생성하고, 2단계에서 Plex 메타 새로고침을 일괄 수행합니다.
  4. **3단계 (외화 자막 누락 진단)**: 자막이 등록되지 않은 영상 폴더에 디스크 자막으로 `.smi`나 한글 `.srt`가 존재할 경우, `.ko.srt` 생성 후 즉시 Plex 메타 새로고침을 지시하여 Plex DB에 정상적인 한국어 자막으로 등록되도록 유도합니다. (이미 `.ko.srt`가 있는 경우 1순위로 인식되어 다른 자막은 건드리지 않음)

##### `Rclone VFS Refresh` 옵션 연동
- 설정 메뉴의 **`Rclone VFS Refresh` (`subtitle_use_vfs_refresh`)** 옵션을 활성화하면, Plex에 메타 새로고침을 지시하기 직전에 **해당 자막/영상 디렉토리에 대해 Rclone `vfs/refresh`를 먼저 호출**합니다.
- **필요성**: Rclone merge(union/mergerfs)나 VFS 캐시 환경에서는 새 파일(`.ko.srt` 등)이 생성되더라도 VFS 디렉토리 캐시가 즉시 갱신되지 않으면 Plex가 새 자막을 즉시 감지하지 못할 수 있습니다. 메타 새로고침 전 `vfs/refresh`를 호출함으로써 Plex가 최신 파일 상태를 즉시 읽을 수 있게 보장합니다.
- **연동 규칙**: Plex Mate의 `스캔` 설정에 등록된 **`VFS 경로 변경 규칙` (`scan_vfs_change_rule`)** 및 Rclone RC 서버 정보를 기반으로 동작합니다.
- **예외 안전성**: Rclone RC 서버에 일시적 장애가 있거나 규칙에 매칭되지 않더라도 메타 새로고침 전체 작업이 중단되지 않고 안전하게 예외 처리됩니다.
